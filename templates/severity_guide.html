CVSS Severity Guide

This page explains what CVSS scores mean and how to interpret the severity ratings shown in search results. Understanding these scores is important for prioritizing which vulnerabilities to address first.

CVSS v3.x Score Ranges
Severity Score Range What It Means Example Action
CRITICAL 9.0 – 10.0 Extremely dangerous. Usually remotely exploitable with no authentication required, often with wormable potential. Patch immediately, consider taking affected systems offline if possible.
HIGH 7.0 – 8.9 Serious vulnerability. May require some conditions to exploit but still poses significant risk. Patch within days. Investigate if any systems may already be compromised.
MEDIUM 4.0 – 6.9 Moderate risk. Often requires local access, user interaction, or specific conditions. Patch within your normal patch cycle (usually 30 days).
LOW 0.1 – 3.9 Minimal risk in most environments. Exploitation is difficult or impact is very limited. Patch when convenient, monitor for changes in exploitability.
NONE / N/A 0.0 or missing No security impact, or the CVE has not been scored yet by NIST. Monitor for score updates. Some CVEs are still being analyzed.
What is CVSS?

CVSS stands for Common Vulnerability Scoring System. It's an open industry standard for assessing the severity of computer system security vulnerabilities. It was created by the National Infrastructure Advisory Council (NIAC) and is maintained by FIRST.org.

The current version is CVSS v3.1, though you'll still see v3.0 and v2.0 scores on older CVEs. The scoring system is designed to be vendor-neutral and consistent.

CVSS does NOT tell you how likely a vulnerability is to be exploited in the real world — just how bad it could be if it were. Tools like EPSS (Exploit Prediction Scoring System) are used alongside CVSS for a fuller picture.

Understanding the CVSS Vector String

The vector string encodes all the metrics used to calculate the score. Example:

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H

Key components:

  • AV (Attack Vector): N=Network, A=Adjacent, L=Local, P=Physical
  • AC (Attack Complexity): L=Low, H=High
  • PR (Privileges Required): N=None, L=Low, H=High
  • UI (User Interaction): N=None, R=Required
  • S (Scope): U=Unchanged, C=Changed
  • C/I/A (CIA Impact): H=High, L=Low, N=None

AV:N + AC:L + PR:N + UI:N is the worst case — remotely exploitable with no conditions.

Famous CVE Examples by Severity
Critical Examples
  • CVE-2021-44228 – Log4Shell (CVSS 10.0) – Remote code execution in Apache Log4j
  • CVE-2017-0144 – EternalBlue (CVSS 8.1 / used in WannaCry) – SMB exploit
  • CVE-2021-34527 – PrintNightmare (CVSS 8.8) – Windows Print Spooler RCE
High/Medium Examples
  • CVE-2014-0160 – Heartbleed (CVSS 7.5) – OpenSSL memory disclosure
  • CVE-2017-5638 – Apache Struts RCE (CVSS 10.0) – Used in Equifax breach
  • CVE-2019-0708 – BlueKeep (CVSS 9.8) – Windows RDP vulnerability
Pro tip: When prioritizing patches, combine CVSS scores with context — is the vulnerable service exposed to the internet? Is it a critical business system? A CVSS 7.0 on an internet-facing server might be more urgent than a CVSS 9.0 on an air-gapped system.
